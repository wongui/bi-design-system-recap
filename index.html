02 Make it effortless

Accessibility
first

User research with real patients drove these calls. A WCAG checklist alone would not have gotten us here.

  • Watching a tired, 65+ reader struggle with the first pass pushed the type ramp up: 18px became the body floor, not 14.
  • Status read by color alone got missed in testing, so every signal now pairs a word and an icon with the color, never color by itself.
  • Tap targets grew and contrast started mattering more than the WCAG minimum, once research showed where real thumbs and real eyes struggled.

06 Three dead ends

What didn’t
work

Before the pipeline that stuck, three different routes into Figma, all eventually abandoned.

  • A token-push plugin Claude built, useful at first, then out of step the moment the token structure moved on.
  • A second plugin built with the Figma agent, a different door onto the same wall.
  • A full rebuild attempt through Figma Make, fast to a UI, but it did not keep the token bindings or the accessibility precision the file already had.

07 My workflow

One hub,
wired to everything

VS Code sat at the center of it all — talking constantly with Figma, calling on Claude to build, and keeping everything synced between the design system folder and GitHub.

  • VS Code was the hub — my main tool and point of contact for almost everything.
  • Figma lived in constant back-and-forth with VS Code: building screens, refining, and stress-testing the system, then feeding what it learned back into code.
  • The design system folder stayed the source of truth, GitHub held the shared backup, and Claude — the LLM — did the actual building, called from inside VS Code.

07 The loop, applied to foundations

Foundations,
built to stay in sync

Every foundation started in code with Claude and was mirrored into Figma step by step. Nothing was handed off once and left to drift.

  • Gave Claude the real inputs first: logo variants, icon sets, accessibility constraints, and reference slides, so every foundation decision had context behind it.
  • Built each foundation in VS Code with Claude Code, then generated and refined a documentation page for it there too.
  • Rebuilt those documentation pages inside Figma with the html.to.figma plugin, then had Claude replicate the same foundations (styles, tokens, effects) to match.
1Feed Claude the source material: logos, icons, accessibility constraints, reference slides
2Build and refine the foundation in VS Code
3Generate its documentation page, refined in VS Code
4Rebuild the documentation page in Figma with html.to.figma
5Direct Claude to replicate styles, tokens & effects into Figma
6Refine continuously, keeping folder and Figma always updated together
07 The loop, applied to components

Components,
built the same way every time

One repeatable loop, run once per component, from first build in VS Code to a refined, documented instance in Figma.

  • Built the component in VS Code with Claude Code, then built its documentation page alongside it.
  • Refined it live using VS Code’s integrated browser, then pushed it into Figma with the /build-figma-component command.
  • Refined the Figma build from VS Code, rebuilt its documentation page there with html.to.figma, and published it to the library, ready to drop into a real screen.
1Build the component in VS Code with Claude Code, then build its documentation page
2Refine it live using VS Code’s integrated browser
3Push it to Figma with /build-figma-component
4Refine the Figma build, then rebuild the documentation page there with html.to.figma
5Publish the library
6Build a real screen, then refine or add variants, keeping folder and Figma always in sync
07 The blocker

Getting VS Code
talking to Figma

None of this works until VS Code can actually reach into Figma. Getting that connection set up in the terminal, so Claude could create and edit inside the Figma file and not just read it, was the first real blocker.

  • Read-only access is the default; writing to Figma from VS Code needs its own setup step, done once per machine.
  • The failure mode is quiet: commands run without errors, but nothing changes in the Figma file.
  • We wrote the fix up once, as a guide, so no one has to rediscover it.
Download the setup guide (.pdf)
!Symptom: Claude, in VS Code, can read the Figma file but can’t create or edit anything in it.
?Cause: terminal-level access to Figma isn’t granted by default. It’s a one-time setup step, easy to miss.
✓Fix: the step-by-step guide below, written from the setup that unblocked it here.

Takeaways

AI accelerates the system, not the judgment
Claude moved fast on tokens, structure, and repetitive builds. Every accessibility call, brand decision, and “is this actually right” moment still needed a human.
Tokens are the leverage point
The frog taxonomy resync and the multi-brand collection are why two brands, six families, and 24+ components didn’t mean 24+ rebuilds.
Figma and code stay in sync only if you make them
The pipeline that worked verifies itself against the documentation page. The ones that didn’t drifted the moment either side changed.
